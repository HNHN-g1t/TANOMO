# 直してから公開されるまで — 手紙をポストに出す話

AIに直してもらったものが、どうやってサイトに出るのか。
**5つの場所を、順番に通っていく**だけ。同時には進まない。

---

## 全体

```
  （１）机の上      （２）封筒        （３）自分の控え  （４）ポスト    （５）掲示板
  直した            入れる            日付を書く        出す            貼られる

  ファイル  ──▶     ステージ  ──▶     コミット  ──▶     GitHub  ──▶     サイト
              add             commit             push        （数分待つ）

  ← ここまで自分のパソコンの中 →                        ← ここからインターネット →
```

**③までは、まだ誰にも見えていない。** ④に出して初めて外に出る。

---

## ひとつずつ

### ① 机の上 ＝ ファイルを直した
AIが書き換えた直後。まだ机に紙が置いてあるだけ。
このまま消したら、なかったことになる。

### ② 封筒に入れる ＝ `git add`
出したい紙だけを封筒に入れる。
机の上の全部を出す必要はない。**選べる**のがここ。

### ③ 日付を書いて封をする ＝ `git commit`
「9月15日、ここを直した」と書いて閉じる。
**ここで初めて記録になる。** あとから「あの日の状態に戻して」ができる。

ただし、まだ自分のパソコンの中。ネットがなくてもここまでは進める。

### ④ ポストに出す ＝ `git push`
GitHub に送る。ここでやっと、外から見えるようになる。

### ⑤ 掲示板に貼られる ＝ 公開
GitHub が自動でサイトを作り直す。**数分かかる**。
押した直後にスマホで見ても、まだ古いことがある。少し待つ。

---

## よくあるつまずき

**「直したのにサイトが変わらない」**
→ ④をやっていないことがほとんど。③で止まっている。
　 ③は自分の机の中なので、世界は何も知らない。

**「押したのに変わらない」**
→ ⑤の数分待ちか、スマホが古い画面を覚えているだけ。
　 少し待つ／ページを読み込み直す。

**「送れませんと言われた」**
→ 自分がいない間に、誰か（＝自動更新の仕組み）が先にポストへ出していた。
　 先に相手の分を受け取ってから、自分の分を出し直す。

---

## ひとことで

> **④に出すまでは、自分の机の上の話。**

「pushしました」と言われたら、④まで済んだということ。
言われていなければ、まだ机の上にある。
