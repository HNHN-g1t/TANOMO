# TANOMO

自分のワークフローに合わせて育てる、Claude Code スキル置き場。

汎用的なアプリではなく「武器」を作る。ここに置いたルールは、頼まなくても自動で効く。

---

## 入っているもの

| スキル | 何をするか | 効く場面 |
|---|---|---|
| [kashikoi-shigoto](skills/kashikoi-shigoto/SKILL.md) | 賢い仕事の型 | 書く・作る・考える・まとめる・レビューする依頼すべて |
| [tsumeru](skills/tsumeru/SKILL.md) | 仕様を詰め切る | 作り始める前。分岐が多い・前提が曖昧なとき |
| [yasumushiki](skills/yasumushiki/SKILL.md) | 引き算のUI設計 | 画面を作る・直すとき |

### 使い分け

```
依頼が来た
   │
   ├─ 画面の見た目の話？ ────────────→ yasumushiki
   │
   ├─ 仕様が固まっていない？ ────────→ tsumeru で詰めてから戻る
   │
   └─ それ以外の制作・レビュー ──────→ kashikoi-shigoto
```

3つは排他ではなく重なる。画面を作るなら `kashikoi-shigoto` で役割と形式を決め、`tsumeru` で仕様を詰め、`yasumushiki` で引き算する。

## 共通原則

3スキルに通底する、このリポジトリ全体の土台。

**1. 足す前に減らす。**
説明文・選択肢・機能・前置き。足したくなったら、まず「なくても成立するか」を試す。説明を書き足したくなったら、それはたいてい作りが弱い。

**2. 測ってから言う。**
「見やすくなりました」「精度が上がりました」で終わらせない。px・件数・実際の色・所要時間。数値がないなら、まだ終わっていない。

**3. 黙って足さない。**
指示になかったことをやった／やらなかったは、必ず明示する。黙って足したものは、あとで必ず揉める。ユーザーが指定した文言は一字一句そのまま。

**4. 前提は置いてよい。ただし見える形で。**
決められることは決めて進む。ただし置いた前提は成果物に添え、違っていれば直せる形にしておく。

**5. 並べて終わりにしない。**
案を複数出したら、推奨を1つ決めて理由を1行で言う。選ばないのは、考えていないのと同じ。

## 導入

```powershell
git clone https://github.com/HNHN-g1t/TANOMO.git
cd TANOMO
.\sync.ps1
```

`sync.ps1` が `skills/` の中身を `~/.claude/skills/` にコピーする。Claude Code を再起動すると読み込まれる。

編集はこのリポジトリ側で行い、`sync.ps1` で反映する。`~/.claude/skills/` を直接いじると差分が消える。

逆方向（`~/.claude/skills/` の変更をリポジトリに取り込む）は `.\sync.ps1 -Pull`。

---

## 追加するとき

1. `FORMAT.md` を読む
2. `skills/<名前>/SKILL.md` を作る
3. `.\sync.ps1` で反映
4. README の表に1行足す
5. commit / push

**1スキル＝1ファイル。** 分割しない。読み込まれるのは `SKILL.md` だけなので、分けた瞬間に中身が届かなくなる。
